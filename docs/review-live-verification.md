# Live review verification — 2026-09-17

## Method and isolation

on localhost:55433. Accounts, rides and bookings were created through HTTP. Only
this disposable database was adjusted to simulate elapsed schedules/deadlines,
cancellations, and legacy null schedules. This schema was generated by Hibernate;
this run does not validate the complete Flyway migration chain or production schema.

unverified. Harness: `/tmp/pw/check.mjs`; output: `/tmp/pw/result.log`;
screenshot: `/tmp/pw/review-form.png`. Browser tooling was installed outside the repos.

The final runnable local harness is `/tmp/review-live-evidence/retest.py`; results
are `/tmp/reviews-live-results.json` and `/tmp/reviews-live-final.log`. These temporary
files are not durable CI tests. Final retesting used the packaged JAR on port 18081.
An intermediate run was invalidated by Maven clean removing classes from a running
app; its ClassNotFoundException errors disappeared on the packaged retest.

## Passing live scenarios

- Anonymous review-workspace access and submission rejected (401).
- Missing target, scores outside 1–5, and overlong comments rejected (400).
- Self/stranger submissions rejected (409); nonexistent public recipient is 404.
- Null comments accepted; pending first review remains absent from public listings.
- Pending amendment retains its review ID; reciprocal submissions publish both sides.
- Public profile and review summary reflect the published score/count.
- Published cycle rejects another edit; a newer ride allows a direct POST without a GET.
- Pending amendment preserves the previous published comment and score.
- Non-admin moderation denied (403); admin hide/restore removes/restores public rating.
- Future, expired, cancelled booking/ride and legacy null-schedule experiences are ineligible.
- An overdue lone review publishes on recipient public-review or author workspace reads.

## Defects reproduced live, then fixed and retested

1. Direct submission after a newer ride required a prior eligibility GET; it failed
   with ReviewWindowClosedException. `submit` now refreshes the stored cycle first.
2. Author workspace reads left overdue submissions pending. The authored mapping
   now evaluates deadline publication before mapping.
3. Cycle refresh cleared overdue content before publication. It now settles that
   submission before clearing the cycle's submitted timestamp.
4. Reciprocal publication ignored cycles. It now requires matching non-null drop-off
   instants; unilateral deadline publication is unchanged.
5. Null reviewers blocked publication after author deletion. Recipient existence is
   now sufficient; counterpart lookup is skipped for anonymized authors.
6. Frontend rendered Write/Update controls for `canSubmit=false` entries.
   `ReviewsToWrite` now filters them for both rendering and counts. The final browser
   smoke test confirmed a locked entry is hidden while a writable entry remains usable.

Five new JUnit regressions capture the backend defects. Fixtures were corrected:
the publication-lock test supplies the prior drop-off, and reciprocal tests identify
the same drop-off with correct author/recipient orientation. Assertions unchanged in intent.

## Limits

This is not whole-feature acceptance. Concurrent request handling,
moderation restore discoverability, and full migration-chain deployment remain unverified.
The deletion test removed the author's booking fixture first to avoid unrelated foreign
keys; unrestricted account deletion is not validated. Rating checks used public summaries,
not every cached driver-rating surface. Boundary timing was simulated by fixture SQL;
exact timing boundaries additionally have existing unit coverage.

## Post-save UX persistence (frontend)

`ReviewsToWrite.svelte` writes a per-cycle dismissal to `localStorage`
(`reviews.dismissed.v1`, key `targetUserId:dropoffAt|rideId`, capped at 200 keys)
immediately when a review is submitted, so a submitted card never reappears — not on
reload, not on other pages (`/account`) in the same browser profile. Backend state stays
authoritative: a submitted-but-unpublished review remains writable server-side
(`canSubmit` stays true until publication or window close); the dismissal is purely a
frontend convenience.

Verified live (`/tmp/pw/e2e-persist.mjs`, 4/4 against dev servers on :8080/:5173):
confirmation replaces the card, reload and account page keep the entry hidden, and the
key is present in localStorage. Full suites `e2e-part1..4.mjs` (13) and
`e2e-saved.mjs` (3) pass; `check` and `lint` are clean. The confirmation banner renders
outside the writable-filtered list because the dismissal removes the entry from that
list in the same tick it is written — rendering it inside the `{#each writable}` loop
would drop it before it is ever visible.
